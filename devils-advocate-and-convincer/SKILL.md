# Devil's Advocate + Master Convincer

A two-phase framework for taking an idea, ruthlessly attacking it, then bulletproofing it for a skeptical audience. The output is structured analysis plus a presentation-ready pitch.

## Why this skill exists

People preparing to pitch, negotiate, or defend an idea systematically underestimate the objections they'll face — and when objections do land, they often respond defensively or generically instead of converting them into momentum. This skill forces the analysis to happen *before* the room, so the user walks in having already heard the hardest version of every pushback and rehearsed a confident, specific counter to each.

The two phases are deliberately asymmetric: Phase 1 is hostile and skeptical; Phase 2 is bulletproof and persuasive. Don't soften Phase 1 to make Phase 2 easier — the value of the skill comes from forcing both to be excellent.

## Capture the input

The full framework wants four things: **Name**, **What** (description), **Why** (value/rationale), **How** (execution plan). It also needs to know the **audience** being convinced.

- If the user provides all of this clearly, proceed.
- If they paste a casual or partial description ("I want to launch X" / "what do you think of this idea?"), extract what you can and infer the rest from context. Don't make the user fill out a template — state your inferences inline at the top of the analysis so they can correct anything you got wrong.
- If the audience isn't stated, infer it from context (a startup founder is usually convincing investors or early customers; a freelancer is usually convincing a client or boss; a manager is usually convincing a team or exec). If multiple audiences are plausible and the objections would differ meaningfully, ask one targeted question — otherwise pick the most likely audience, name it explicitly, and proceed.
- If the user's input is so thin that meaningful analysis isn't possible (e.g., "stress-test my startup" with no detail), ask for a one-paragraph description of what they're building and who they're pitching, then proceed.

## Phase 1: Devil's Advocate

Imagine a panel of skeptical, intelligent experts whose only job is to kill this idea. The goal is to surface every realistic objection so the user isn't blindsided in the actual room. Soft objections waste the user's time — push for specificity.

Surface objections across these five categories:

1. **Logical Weaknesses** — flawed reasoning, unproven assumptions, market-fit problems, feasibility gaps, internal contradictions.
2. **Practical Barriers** — cost, time, execution risk, technical limitations, resource and team constraints, regulatory friction.
3. **Social / Political Risks** — stakeholder resistance, competitive moats, cultural fit, organizational politics, brand or reputational risk.
4. **Psychological Pushback** — skepticism, fear of change, ego conflicts, status threats, sunk-cost attachments in the audience.
5. **Worst-Case Scenarios** — what catastrophic failure looks like and what triggers it. Be concrete about the failure mode, not just the outcome.

Aim for **2–4 substantive objections per category**, calibrated to the actual idea. If a category genuinely doesn't apply, say so in one sentence rather than padding with filler.

**What "substantive" means:** a substantive objection names a specific mechanism. Not "this could be expensive" but "the unit economics break below 10,000 users because CAC at $40 doesn't match an LTV of $35 — and getting to 10,000 users requires paid acquisition you haven't budgeted for." If you find yourself writing an objection that could apply to almost any idea, sharpen it or drop it.

## Phase 2: Master Convincer

For each objection in Phase 1, produce a response with these five elements. They build on each other — reframe first to shift the ground, then deliver a concrete fix, then layer in persuasion and emotion, then close.

- **Reframe**: turn the objection into a strength, opportunity, or moot concern. The reframe should feel earned, not slippery.
- **Solution**: a concrete, actionable step or mechanism that addresses the concern. Specific is the whole point. "Address through clear communication" is not a solution. "Run a 30-day paid pilot with two design partners, success-gated on a 20% retention lift" is a solution.
- **Persuasion technique**: name the specific tactic in use (see the menu below) and apply it to this objection. Naming the technique forces it to actually do work.
- **Emotional hook**: tap the audience's values, ambitions, fears, or hidden incentives. What do they actually care about beyond the surface objection?
- **Closing line**: one crisp sentence the user can deliver in the room that ends the argument with confidence.

### Persuasion technique menu

Pull from these explicitly — name the technique when you use it. Match the technique to the audience and objection rather than spraying them randomly.

- **Anchoring** — lead with an extreme reference point so the actual ask feels reasonable.
- **Framing** — reposition the same fact in a different light (cost → investment; risk → optionality).
- **Social proof** — cite specific named comparables who've done this and won.
- **Authority bias** — invoke credible third parties, research, precedent, or experts.
- **Scarcity** — emphasize what's lost by inaction or what's limited about the window.
- **Loss aversion** — people fear losing more than they value gaining. Make inaction the risky option.
- **Storytelling** — a concrete narrative beats abstract argument. Pick a vivid case.
- **Contrast principle** — set the option next to a clearly worse alternative.
- **Reciprocity** — offer something concrete first to invite a return move.
- **Commitment & consistency** — get small public agreements that align with the bigger ask.
- **Specificity & numbers** — vague claims feel like spin; precise numbers feel like truth.

## Final Narrative

After both phases, write a **200–400 word "presentation-ready" pitch** that weaves the strongest reframes, solutions, and emotional hooks into a smooth, confident argument. This is what the user would actually say in the room — flowing prose, no bullets, no tables, ready to be delivered out loud.

Open with the strongest emotional hook or anchor, walk through the two or three most important objection-to-response transitions in narrative form, and close on the strongest closing line. The narrative should sound like a person who has already won the room, not a person reading a checklist.

## Output format

Use this structure exactly:

```
# [Idea Name] — Devil's Advocate & Convincing Strategy

## Inferred context
- Audience: [who the user is convincing]
- What I assumed: [any inferences you made about the idea]
*(Skip this section if the user provided full structured input.)*

## Executive Summary
[3–5 sentences: core strengths, the two or three biggest risks, overall verdict on whether the idea survives scrutiny.]

## Phase 1: Objections

| Category | Objection | Why it bites |
|---|---|---|
| Logical Weakness | … | … |
| Practical Barrier | … | … |
| Social/Political Risk | … | … |
| Psychological Pushback | … | … |
| Worst-Case Scenario | … | … |

## Phase 2: Convincing Responses

| Objection | Reframe | Solution | Technique | Hook | Closing line |
|---|---|---|---|---|---|

## Final Narrative
[200–400 words of flowing pitch.]
```

If the user is on mobile or the table would be unreadably wide, drop the Phase 2 table and use a paragraph-per-objection layout instead (same five elements, just stacked vertically under each objection heading). Same content, different layout — don't lose information just to fit a table.

## Quality bar

A few traps to actively avoid:

- **Generic objections.** "It's expensive" / "competition is fierce" / "execution is hard" apply to every idea ever conceived. They're not objections, they're filler. Push every objection toward the specific mechanism that makes it bite for *this* idea.
- **Hand-wavy solutions.** "Communicate the value clearly" is not a solution. "Address concerns proactively" is not a solution. A real solution names a step, a mechanism, a number, or a tactic.
- **Symmetric softening.** Don't weaken Phase 1 to make Phase 2 easier. Take the hardest version of each objection and *then* beat it. The whole skill is worthless if Phase 1 isn't ruthless.
- **Unnamed persuasion.** "Use persuasion" is not a technique. Pick from the menu, name it, and apply it.
- **Audience drift.** Investor objections, client objections, internal team objections, and customer objections are different species. If you find Phase 2 leaning on the wrong incentives for the named audience, reroute it.
- **Length over substance.** A short, sharp analysis beats a bloated one. Three pointed objections per category beat six filler ones.

## When the input is light

If the user gives you a one-liner ("stress-test Batota for me"), don't refuse and don't hallucinate detail. Either:
- Pull from earlier in the conversation if there's context, name what you pulled, and proceed; or
- Ask one focused question that unblocks the analysis (usually: "Who are you pitching this to, and what's the specific decision you want from them?").

When in doubt, proceed with stated assumptions rather than stalling. A draft analysis with clear inferences is more useful than a perfect questionnaire.
